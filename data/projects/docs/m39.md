# Bare-metal STM32: GPIO, UART, I2C and SPI drivers without the HAL

**Goal.** An STM32 board that boots from your own startup file and linker script into your `main()`, configures its clocks, and talks to real sensors through interrupt-driven UART, I2C and SPI drivers written against the reference manual, with no vendor HAL.

**Why.** Skills: reading reference manuals and datasheets, interrupts and the NVIC, linker scripts and the C runtime start-up, and logic analysers. It removes the last layer of magic between your C and the silicon, and every later embedded project (`m40`, `m44`, `m46`, `m47`) builds on these drivers. Resources: `ut-embedded-shape-the-world`, `making-embedded-systems`, `phils-lab`.

**Scope.** MVP: vector table and reset handler in C or assembly, `.data` copy and `.bss` zeroing, PLL configuration to the board's maximum clock, SysTick, a typed register layer, GPIO, interrupt-driven UART with TX and RX ring buffers, polled-then-interrupt I2C with error recovery, SPI with an optional DMA path. Real devices: an IMU or temperature sensor on I2C, a small display on SPI. Stretch: a `printf` retargeted to the UART, a DMA SPI transfer for the display, unit tests of the ring buffer on the host.

**Architecture.** Reset handler → `SystemInit` (clocks, flash wait states) → C runtime init → `main()`. Drivers sit on a typed register layer generated from or checked against the SVD file. Interrupt handlers only move bytes between peripherals and ring buffers; application code reads and writes the buffers.

```
reset ─▶ startup.c (.data, .bss) ─▶ clocks ─▶ main()
                                              │
   app ◀─▶ ring buffers ◀─▶ ISRs ◀─▶ UART / I2C / SPI regs ◀─▶ sensors, display
```

**Stack.** C11, `arm-none-eabi-gcc`, GNU ld, Make or CMake, OpenOCD and GDB over the on-board ST-LINK, the STM32 reference manual and the sensor datasheets, sigrok/PulseView for the logic analyser.

**Parts and budget.**
- STM32 Nucleo-F446RE or similar with an on-board ST-LINK ($15–25)
- 8-channel 24 MHz USB logic analyser ($10–20)
- USB-serial adapter, 3.3 V ($5–10)
- I2C IMU or temperature breakout (MPU-6050, BMI160, TMP117) ($5–15)
- SPI display (SSD1306 OLED or ST7735 LCD) ($5–12)
- Second breakout sensor for bus sharing ($5–15)
- Total: about $45–100

**Milestones.** Startup file, linker script, clock tree and a blinky (8 h) · typed register layer, GPIO and SysTick (6 h) · interrupt-driven UART with ring buffers (7 h) · I2C driver reading a real sensor (8 h) · SPI driver drawing on the display (6 h) · logic-analyser captures and write-up (5 h). Total 40 h.

**Done when.** The map file shows your vector table at the start of flash and no vendor start-up code. The clock is verified by outputting SYSCLK on MCO and measuring it within 0.1 %. The UART echoes 1 MB at 115 200 baud with no lost bytes while the main loop is busy. I2C reads the sensor's ID register and streams readings at 100 kHz and 400 kHz, and recovers from a bus held low. SPI updates the display at 8 MHz or more. The README shows a decoded logic-analyser capture of each bus.

**Measure and report.** Flash and RAM size of the firmware against a HAL-based blinky; interrupt latency from a GPIO edge to the ISR toggling a pin, in cycles; UART throughput and dropped-byte count; I2C and SPI transaction times from the captures; current draw at full clock.

**Pitfalls.** Forgetting to enable a peripheral's clock in RCC and reading zeros forever. Flash wait states left at zero after raising the clock, so the core hard-faults. `volatile` missing on shared ring-buffer indices. I2C's address shifted twice or not at all. A ring buffer whose full and empty conditions are the same comparison.

**References.** ut-embedded-shape-the-world, making-embedded-systems, phils-lab, cmu-15-213, cert-embedded-shape-the-world, cert-arm-education.

**Write-up.** The boot sequence as a diagram, the linker script explained line by line, the three bus captures, the size and latency table, and a paragraph on what you would generate from the SVD next time.
