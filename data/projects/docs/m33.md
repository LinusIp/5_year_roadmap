# CUDA GEMM: naive, tiled, tensor cores, with a roofline plot

**Goal.** Three CUDA matrix-multiply kernels (naive, shared-memory tiled and tensor-core), each correct against cuBLAS, benchmarked in GFLOP/s at several sizes, placed on a roofline for your GPU, and profiled in Nsight Compute until the bottleneck of each is explained.

**Why.** GEMM is where most inference time goes, and the roofline is the tool for reasoning about any kernel. It covers `inference-engineering/cuda`, `inference-engineering/writing-custom-kernels`, `inference-engineering/roofline-model`, `inference-engineering/arithmetic-intensity`, `inference-engineering/ops-byte-ratio` and `inference-engineering/profiling-performance`, and builds CUDA, the memory hierarchy and performance analysis.

**Scope.** MVP: an FP32 naive kernel with coalesced access; a shared-memory tiled FP32 kernel with register blocking (each thread computes a 4×4 or 8×8 sub-tile); a tensor-core kernel with FP16 inputs and FP32 accumulation using WMMA; a test harness against cuBLAS; benchmarks at N = 512, 1 024, 2 048 and 4 096 plus one non-square shape; the roofline plot. Stretch: vectorised loads, double buffering with `cp.async`, a CUTLASS comparison, a Triton version.

**Architecture.** A host driver fills matrices with seeded random data, runs cuBLAS as the reference, runs each kernel, compares the results, and times every kernel with CUDA events over 20 iterations after warm-up. The roofline script takes peak FLOP/s and DRAM bandwidth (spec sheet plus a measured bandwidth test) and each kernel's achieved FLOP/s and bytes moved from Nsight Compute.

```
host: init A, B ─▶ cuBLAS (reference C) ─▶ kernels {naive, tiled, wmma} ─▶ compare
                                                    │ CUDA events
                          GFLOP/s table ─▶ roofline.py ◀── ncu metrics
data path: global ─▶ shared tile ─▶ registers / fragments ─▶ tensor cores ─▶ C
```

**Stack.** CUDA 12, C++17, CMake, cuBLAS, Nsight Compute and Nsight Systems, Python with Matplotlib, one NVIDIA GPU with tensor cores (Turing or newer).

**Milestones.** Harness, cuBLAS reference and naive kernel (6 h) · shared-memory tiled kernel with register blocking (8 h) · tensor-core WMMA kernel (8 h) · benchmarks across sizes (4 h) · roofline and Nsight Compute analysis (6 h) · write-up (3 h). Total 35 h.

**Done when.** Every kernel matches cuBLAS at every size within a stated tolerance (relative error under 1e-4 for FP32, under 1e-2 for FP16 inputs). GFLOP/s are reported at five shapes with cuBLAS alongside; at N = 4 096 the tiled FP32 kernel reaches at least 50 % of cuBLAS SGEMM, and the tensor-core kernel beats your best FP32 kernel. The roofline shows the GPU's compute and bandwidth ceilings and every kernel at N = 4 096. For each kernel, Nsight Compute evidence (memory throughput, warp stall reasons, occupancy) backs a one-paragraph diagnosis of what limits it.

**Measure and report.** GFLOP/s and percentage of cuBLAS per kernel and size; measured arithmetic intensity (FLOP per DRAM byte) against the theoretical value; achieved DRAM bandwidth; the top stall reason per kernel; your GPU's ops:byte ratio and where the ridge point falls.

**Pitfalls.** Uncoalesced loads in the naive kernel blamed on compute. Shared-memory bank conflicts in the tiled kernel. Timing with host clocks and no synchronisation, or including the first launch. Sizes that are not a multiple of the tile, with no bounds checks. Judging FP16 results with an FP32 tolerance.

**References.** siboehm-cuda-matmul, pmpp-book, cuda-guide, roofline, nsight-compute-docs, horace-he-brrr.

**Write-up.** The roofline chart, the GFLOP/s table against cuBLAS, one Nsight Compute screenshot per kernel with its diagnosis, and the next optimisation you would make.
