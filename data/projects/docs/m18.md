# OpenGL mini-engine: deferred shading, shadows, PBR, glTF loading

**Goal.** A small OpenGL engine that loads a scene file and glTF assets, renders them through deferred shading with shadow maps, HDR and a PBR metallic-roughness pipeline with image-based lighting, and explains every pass in its README.

**Why.** Game Developer roadmap: `game-developer/opengl`, `game-developer/glsl`, `game-developer/graphics-pipeline`, `game-developer/shadow-map`, `game-developer/physically-based-rendering`, `game-developer/metallicity`, `game-developer/microsurface-scattering` and `game-developer/tone-reproduction`. Skills: render passes, PBR and engine structure. LearnOpenGL teaches each technique alone; this project makes them coexist in one frame, which is what the Vulkan work and the capstone engine need.

**Scope.** MVP: a JSON scene file, glTF loading through a library, a G-buffer pass, a lighting pass for directional and point lights, shadow mapping with PCF for the sun, HDR with exposure and ACES tone mapping, metallic-roughness PBR with an irradiance map, a prefiltered environment map and a BRDF lookup table. Stretch: cascaded shadow maps, SSAO, bloom, hot-reloading shaders.

**Architecture.** An asset layer loads meshes, textures and materials once and hands out handles. The scene graph holds nodes with transforms, meshes and lights. The renderer runs a fixed list of passes per frame: shadow depth, G-buffer, lighting with IBL, forward pass for the skybox, tone map. Precomputation of the IBL maps runs once at startup.

```
scene.json ─▶ assets ─▶ scene graph
                           │
shadow pass ─▶ G-buffer ─▶ lighting (+IBL) ─▶ sky ─▶ tone map ─▶ screen
```

**Stack.** C++20, OpenGL 4.5 core with GLFW and glad, cgltf or tinygltf, stb_image for HDR environment maps, GLM, Dear ImGui for controls, RenderDoc for captures.

**Milestones.** Engine skeleton: scene file, asset loading through a library, resource handles (8 h) · Deferred G-buffer and lighting pass (8 h) · Shadow mapping with PCF (6 h) · PBR metallic-roughness with IBL, HDR and tone mapping (10 h) · RenderDoc capture explained pass by pass, profiling and README (8 h). Total 40 h.

**Done when.** Sponza and the glTF MetalRoughSpheres sample load from a scene file without code changes. With 64 point lights and one shadowed sun, the engine holds 60 frames a second at 1080p on your GPU. The spheres' appearance matches the Khronos sample viewer side by side across the roughness and metallic grid. The OpenGL debug output reports no errors. The README walks through a RenderDoc capture, one image per pass.

**Measure and report.** GPU time per pass from timer queries; frame time against light count from 1 to 256 for deferred against a forward baseline; G-buffer memory at 1080p; shadow-map resolution against visible aliasing; IBL precomputation time.

**Pitfalls.** Treating colour textures as linear, or normal and roughness maps as sRGB. Normal maps without a correct tangent frame, so lighting looks fine until you rotate the model. Shadow acne and peter-panning from a single global bias. Writing HDR values into an 8-bit G-buffer target. Measuring CPU time around draw calls, which says nothing about the GPU; use timer queries.

**References.** learnopengl, rtr4, paper-microfacet, game-engine-architecture, utah-cs6610, m10.

**Write-up.** A screenshot of Sponza with shadows and IBL, the sphere grid next to the reference, the pass-by-pass RenderDoc walkthrough, the per-pass timing table, and what you would move to Vulkan first.
