# RISC-V subset CPU on the FPGA, running your own C program

**Goal.** An RV32I core of your own design, first single-cycle and then pipelined, that passes the official RV32I tests in simulation and runs a C program compiled with riscv-gcc on the project 42 FPGA, printing over a memory-mapped UART.

**Why.** Skills: CPU design (datapath, control, the ISA as a contract), pipelining (hazards, forwarding, stalls, flushes), and toolchains (crt0, linker scripts, ELF to memory image). It closes the loop between `harris-ddca`, `mit-6-004` and the bare-metal start-up you wrote in `m39`, on the hardware of `m42`.

**Scope.** MVP: every RV32I instruction, with `fence` as a no-op and `ecall` and `ebreak` trapping; a single-cycle core; a five-stage pipeline with forwarding, load-use stalls and branch flushes; block-RAM instruction and data memories; a memory-mapped UART and GPIO; a C program built with your linker script. Stretch: the M extension, a cycle counter CSR, branch prediction, running CoreMark.

**Architecture.** Fetch reads the instruction memory at the PC; decode reads the register file and generates immediates and control; execute runs the ALU and resolves branches; memory accesses data RAM or a peripheral chosen by an address decoder; write-back writes the register file. A hazard unit forwards results and inserts bubbles.

```
IF ─▶ ID ─▶ EX ─▶ MEM ─▶ WB
 ▲     ▲     │      │
 │     └─ forward ◀─┘          address decoder
 └── branch flush ─┘           ├─ data RAM
                               ├─ UART (0x1000_0000)
                               └─ GPIO (0x1000_1000)
```

**Stack.** SystemVerilog; Verilator for simulation, with a C++ harness that loads ELF files; the riscv-tests suite (`rv32ui-p-*`); `riscv64-unknown-elf-gcc` with `-march=rv32i -mabi=ilp32`; the project 42 FPGA toolchain; GTKWave.

**Parts and budget.**
- The FPGA board of project 42 ($0, reused)
- USB-serial adapter if that board has no USB UART ($0–10)
- Total: about $0–10

**Milestones.** Single-cycle RV32I core in simulation (10 h) · riscv-tests harness, all rv32ui tests passing (6 h) · five-stage pipeline with forwarding, stalls and flushes (10 h) · FPGA build with block RAM, UART and GPIO (6 h) · crt0, linker script, a C program printing over the UART, and write-up (8 h). Total 40 h.

**Done when.** Every `rv32ui-p` test (except `fence_i`, which needs Zifencei) passes on both the single-cycle and the pipelined core in Verilator, run by one script in CI. The pipelined core also passes a randomised comparison against a reference simulator (Spike or your own ISA model) over 100 000 instructions. On the FPGA, a C program compiled with your linker script prints "hello", computes the CRC-32 of a 4 KB buffer that matches the host's, and blinks a GPIO. Timing closes at the reported clock frequency.

**Measure and report.** CPI of each core on three programs (CRC-32, a sort, a matrix multiply); maximum clock frequency and LUT, flip-flop and block-RAM use for both cores; stall and flush counts from a simulation trace; performance in instructions per second against the project 39 microcontroller on the same CRC.

**Pitfalls.** Sign extension of immediates (especially B- and J-type bit scrambles). Writing to register x0. Load-use hazards forwarded from the wrong stage. Byte and half-word stores without byte enables. A linker script that puts `.data` in ROM without copying it to RAM at start-up.

**References.** harris-ddca, mit-6-004, nand2tetris, cmu-15-213, project-f, m42, m39.

**Write-up.** A pipeline diagram, a waveform of a load-use stall, the test-pass table, the CPI and frequency table for both cores, a photo of the UART output, and a paragraph on adding the M extension.
