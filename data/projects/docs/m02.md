# CLI habit tracker in Python, tests and CI, on PyPI

**Goal.** A habit-tracking command-line tool, installable with `pip install` from PyPI, with tests, linting and a release pipeline that publishes every tagged version.

**Why.** Small code, finished properly. It builds argparse or Typer, pytest, packaging and GitHub Actions, and the roadmap nodes `software-architect/python`, `software-architect/tdd`, `software-architect/ci-cd` and `software-architect/git`. Everything later on the roadmap ships through the same loop: a test suite, a pipeline, a tagged release.

**Scope.** MVP: `habit add`, `habit done`, `habit list`, `habit stats` (streaks, weekly completion rate) and `habit export --csv`; storage in SQLite under the user's data directory; `--help` on every command; a pytest suite; Ruff lint; CI on every push; publish on tag through PyPI trusted publishing. Stretch: a `--json` output mode, a reminder via cron, a Textual TUI, Hypothesis property tests for the streak logic.

**Architecture.** A thin CLI layer parses arguments and formats output. A service layer holds the rules: what counts as a streak, how a missed day is treated. A storage layer hides SQLite behind a small repository interface, so tests can use an in-memory database. Dates come from an injected clock, so the summaries are testable on any day.

```
argv ─▶ cli (Typer) ─▶ service (streaks, stats) ─▶ store (SQLite)
                              ▲
                     clock ───┘        export ─▶ CSV
```

**Stack.** Python 3.12, Typer or argparse, sqlite3 from the standard library, platformdirs, pytest with pytest-cov, Ruff, a `pyproject.toml` with a hatchling or setuptools backend and a `[project.scripts]` entry point, GitHub Actions, TestPyPI then PyPI.

**Milestones.** Data model, storage and the add and done commands (5 h) · list, stats and export with streak logic (5 h) · pytest suite with an injected clock (5 h) · packaging, entry point and help text (4 h) · GitHub Actions lint, test and tag-to-PyPI release (4 h) · README and an install test on a clean machine (2 h). Total 25 h.

**Done when.** `pipx install <name>` on a fresh machine or container gives a working `habit` command, and every subcommand has a useful `--help`. pytest passes with at least 90 % line coverage of the storage and summary modules, including streaks across a month end, a leap day and a missed day. CI runs Ruff and pytest on Python 3.11, 3.12 and 3.13 on every push, and pushing a `v*` tag publishes that version to PyPI with no manual step.

**Measure and report.** Test count and coverage; CI wall-clock time; wheel size; start-up time of `habit --help` (aim for under 150 ms); how many days you have used it yourself.

**Pitfalls.** Streak logic that breaks on time zones or daylight-saving changes because it compares datetimes where it needs dates. Writing the database next to the code, which fails once installed into site-packages. A package name already taken on PyPI, found on release day. Tests that touch the real home directory. Publishing with a long-lived API token instead of trusted publishing.

**References.** github-actions-docs, fluent-python, missing-semester, w-ci-pipeline, w-property-tests.
