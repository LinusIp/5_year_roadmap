# ML Zoomcamp midterm project, deployed

**Goal.** A trained tabular model behind a Dockerised HTTP prediction service, deployed at a public URL that a stranger can call with the sample request in the README.

**Why.** It is the first end-to-end machine-learning loop you own: data, features, model selection, packaging and serving. It builds scikit-learn, Flask or FastAPI, Docker and deployment, and touches `ai-engineer/training`, `ai-engineer/inference`, `inference-engineering/model-evaluation`, `inference-engineering/containerization` and `inference-engineering/docker`. The serving half is the seed of every later service on the roadmap; the evaluation half is the habit every later study depends on.

**Scope.** MVP: one public dataset of 5k–100k rows, EDA, feature work, at least three models (a linear baseline, a tree ensemble, a gradient-boosted model) compared on a held-out set, a `train.py` that reproduces the winner, a `/predict` endpoint in a Docker image, a cloud deploy. Stretch: a small web form, input validation with Pydantic, a model card, a scheduled retrain.

**Architecture.** The notebook explores the data and settles the features. `train.py` reads the raw CSV, applies the same preprocessing pipeline (a scikit-learn `Pipeline` or `DictVectorizer`), fits the chosen model with the tuned parameters and writes one artefact file. The service loads that artefact once at start-up, validates JSON input and returns a prediction and a probability. A Dockerfile pins Python and library versions; the cloud host runs the image.

```
data.csv ─▶ notebook (EDA, CV) ─▶ train.py ─▶ model.bin
                                                │
client ─▶ HTTPS ─▶ container: FastAPI ─▶ load ◀─┘ ─▶ prediction JSON
```

**Stack.** Python 3.12, pandas, scikit-learn, XGBoost or LightGBM, FastAPI (or Flask) under uvicorn or gunicorn, uv or pipenv for locked dependencies, Docker, and one host: Fly.io, Render, Google Cloud Run or AWS Elastic Beanstalk.

**Milestones.** Dataset choice and EDA notebook (6 h) · feature work and three models compared with cross-validation (8 h) · training script and prediction service (5 h) · Docker image with pinned dependencies (3 h) · cloud deploy and README with a sample request (5 h) · self-review against the Zoomcamp criteria (3 h). Total 30 h.

**Done when.** The notebook compares at least three models on a held-out test set that was never used for tuning, with one metric chosen and justified up front. `python train.py` rebuilds the deployed artefact from scratch in under 10 minutes. `docker run` serves the model locally, and the deployed URL answers the README's `curl` request with a valid prediction. Every item of the Zoomcamp's midterm review criteria is ticked, and the submission passes peer review.

**Measure and report.** The held-out metric (ROC AUC or RMSE) for every model, with its cross-validation mean and standard deviation; the gap between the best model and the simplest baseline; prediction latency p50 and p99 over 1 000 requests to the deployed service; the Docker image size.

**Pitfalls.** Leakage: fitting the scaler or encoder on the whole dataset before the split, or a feature that encodes the target. Tuning on the test set until it stops being a test set. A notebook and a `train.py` whose preprocessing drifts apart, so the service sees different features from training. An unpinned dependency that breaks the image a month later. A free-tier host that sleeps, so the first request takes 30 seconds.

**References.** ml-zoomcamp, cert-ml-zoomcamp, mlops-zoomcamp, docker-get-started, kaggle-learn.

**Write-up.** The problem in two sentences, the model comparison table, the deployed URL with a copy-paste request and response, how to run it locally in three commands, and what you would try next with more data.
