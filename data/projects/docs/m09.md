# Build your own Git in Python

**Goal.** A Python tool that implements init, hash-object, cat-file, add, write-tree, commit, log and checkout with byte-compatible objects, so real git reads the repositories it writes and it reads the repositories real git writes.

**Why.** Git is a content-addressed object store with a thin layer of refs on top; building it teaches content-addressed storage, zlib and binary file formats. It extends `software-architect/git` from using Git to knowing exactly what it stores, and makes the index and the object model concrete.

**Scope.** MVP: loose objects (blob, tree, commit) hashed with SHA-1 and compressed with zlib; the version 2 index file for add; write-tree from the index; commit with parent, author, committer and message; HEAD and branch refs; log by walking parents; checkout of a branch or commit into the working tree; round-trip tests against real git. Stretch: status and diff, reading packfiles, clone over the smart HTTP protocol, annotated tags.

**Architecture.** The object store hashes `type size\0content`, compresses it and writes it under `.git/objects/xx/…`. The index layer parses and writes the binary index with its stat fields and trailing checksum. Tree building turns flat index paths into nested tree objects. Refs map names to hashes. Each command is a thin function over these layers.

```
files ─▶ add ─▶ index ─▶ write-tree ─▶ tree ─▶ commit ─▶ refs/heads/main
                  │                      │         │
                  └──── object store (SHA-1, zlib) ◀┘
checkout: ref ─▶ commit ─▶ tree ─▶ working files
```

**Stack.** Python 3.12 standard library only (hashlib, zlib, struct, os, pathlib), pytest, and real git 2.4x as the oracle in tests.

**Milestones.** Object store, hash-object and cat-file (4 h) · trees and write-tree (4 h) · index format and add (6 h) · commit, refs and log (4 h) · checkout (3 h) · round-trip tests with real git and write-up (4 h). Total 25 h.

**Done when.** For a test repository of at least 50 files in nested directories, your `hash-object` and `write-tree` produce exactly the hashes git produces. `git fsck` reports no errors on a repository written only by your tool, and `git log` shows its commits. Your `log` and `checkout` work on a repository made by git. All of this runs as pytest round-trip tests in CI.

**Measure and report.** Round-trip test count and pass rate; time to add and commit 1 000 files against git; object count and on-disk size against git for the same history with loose objects only; lines of code per command.

**Pitfalls.** Tree entries sorted wrongly: git sorts a directory as if its name ended in `/`. Mode strings: trees are `40000`, not `040000`. Opening files in text mode and letting newline translation change the bytes. Index entries not padded to 8-byte boundaries. Time-zone offsets missing or wrong in commit headers.

**References.** build-your-own-x, w-git-internals, missing-semester.

**Write-up.** A diagram of one commit's object graph, the round-trip test table, the format detail that took longest, and what packfiles would add.
