# Build your own shell in C: pipes, redirects, jobs

**Goal.** A Unix shell in C that parses command lines, runs pipelines of any length with input and output redirection, provides cd, exit, export, jobs, fg and bg, and handles Ctrl-C and Ctrl-Z as bash does.

**Why.** It is the clearest way into processes, file descriptors, signals and parsing: fork, exec, dup2, pipe, waitpid, process groups and terminal control. Of the catalogue's roadmaps only `software-architect/linux-unix` touches it; the matching material is the CS:APP shell lab (csapp-labs, cmu-15-213) and the process chapters of ostep.

**Scope.** MVP: a tokenizer with quotes and escapes; a parser for pipelines, `<`, `>`, `>>` and `&`; the six built-ins; PATH lookup; `$VAR` expansion; a job table with foreground and background jobs; SIGINT, SIGTSTP and SIGCHLD handling; a comparison test script. Stretch: `&&` and `||`, `2>&1`, history with line editing, globbing, subshells.

**Architecture.** The reader gets a line; the lexer turns it into tokens; the parser builds a pipeline of commands, each with argv and redirections. The executor creates one process group per job, forks each stage, wires pipes with dup2, applies redirections and execs. Built-ins that change shell state run in the shell process itself. The job controller owns the table, hands the terminal to the foreground group with tcsetpgrp, and reaps children from the SIGCHLD handler.

```
line ─▶ lexer ─▶ parser ─▶ pipeline { cmd | cmd | cmd, <, >, & }
                               │
                  executor: fork ─▶ pipe/dup2 ─▶ execvp
                               │
                 job table ◀── SIGCHLD, SIGINT, SIGTSTP (tcsetpgrp)
```

**Stack.** C11, POSIX APIs on Linux, GCC with sanitizers, Make, a Bash or Python test harness, strace and gdb for debugging.

**Milestones.** Lexer and parser with unit tests (6 h) · fork, exec, PATH lookup and built-ins (5 h) · pipes and redirection (6 h) · job control and signals (8 h) · comparison test script against bash and write-up (5 h). Total 30 h.

**Done when.** The harness runs 30 command lines (pipelines of 1–5 stages, every redirection, quoting, variables, failing commands) through your shell and through bash, and stdout, stderr and exit status match for all 30. `sleep 100 &`, `jobs`, `fg`, Ctrl-Z, `bg` and Ctrl-C behave as in bash, checked with a scripted session. After 1 000 pipelines the shell holds only file descriptors 0, 1 and 2, and after 100 background jobs finish there are no zombies.

**Measure and report.** The 30-case pass table; open file descriptors after 1 000 pipelines; zombie count after a burst of 100 background jobs (must be 0); wall time of a 5-stage pipeline in your shell against bash.

**Pitfalls.** Unused pipe ends left open, so the reader never sees EOF and the pipeline hangs. A race between fork and adding the job to the table, so SIGCHLD arrives for a job you do not know yet; block SIGCHLD around it. Children left in the shell's process group, so Ctrl-C kills the shell. Calling printf or malloc inside a signal handler. Running cd in a child, where it changes nothing.

**References.** csapp-labs, cmu-15-213, ostep, beej-c, missing-semester, build-your-own-x.

**Write-up.** A short terminal recording, a diagram of the file-descriptor tables for `a | b | c > out`, the comparison table, and the job-control bug that took longest to find.
